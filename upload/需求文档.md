## 项目名称：决策回响 · AI决策力大富翁沙盘（MVP）

### 一、项目概述

这是一个**单人在线AI决策推演游戏**。玩家选择一个身份角色，沿着一条固定的主线任务链前进。每一步需要与AI对话来完成挑战，中途会随机触发机遇或危机事件。系统最终根据玩家的对话质量和决策能力给出评分和结局。

**核心教学目的**：让学员在模拟场景中反复练习与AI的结构化对话能力（提示词技巧），并获得即时反馈。

**产品基调**：冷静、理性、深邃的决策推演氛围。不要喧闹、花哨、综艺化的设计。

---

### 二、核心游戏流程（必须严格遵循）

1.  **欢迎页** → 玩家点击“开始推演”
2.  **选择角色**（如“社区小店主”或“42岁被裁者”），不同角色初始资源和AI人设不同
3.  **进入游戏主循环**，按以下顺序推进：

```
主线任务1 → 主线任务2 → ⚡事件触发点 → 主线任务3 → 主线任务4 → 🔄结算点 → 主线任务5 → ⚡事件触发点 → ... → 主线任务N → 🏁最终结算
```

**详细说明**：
-   **主线任务**：玩家必须完成的AI对话挑战。提交后系统评分，不满意可支付资源重做。
-   **事件触发点**：固定位置，必定触发。从卡池中随机抽取一张事件卡（可能是危机或机遇）。
-   **结算点**：固定位置。展示阶段得分、开启道具商店、显示阶段性总结。
-   **最终结算**：根据总分匹配结局称号，生成决策风格报告。

### 三、核心机制详解

#### 1. 主线任务
-   每个任务包含：标题、情景描述、具体任务要求、时限、评分权重。
-   玩家在AI对话面板中与AI协作完成任务。
-   玩家可填写一个“最终决策结论”文本框（可选，用于总结AI对话中的关键产出）。
-   点击“提交”后，系统调用AI裁判API进行评分。
-   评分不满意可支付“决策币”重做（重做次数越多，花费递增）。

#### 2. 随机事件（两种类型）

**机遇卡（可选）**：
-   弹出后，玩家可选择“接受”或“放弃”。
-   接受 → 完成一个额外小任务，获得奖励（加分、决策币、道具）。
-   放弃 → 无事发生，继续主线。

**危机卡（强制）**：
-   弹出后，玩家无法跳过。
-   玩家先**掷骰子**，骰子点数决定危机的严重程度（1=最坏，6=最轻）。
-   骰子结果展示一段叙事文本 + 具体惩罚数值。
-   玩家可支付决策币“缓冲”惩罚（减轻损失）。
-   然后玩家必须用AI对话应对危机，评分结果与骰子结果共同决定最终扣分。

#### 3. 资源系统
-   **决策币**：游戏内货币。用途：重做任务、购买道具、缓冲危机。
-   **道具**：可在商店购买，提供策略优势（如“重掷骰子”、“跳过危机”、“指定AI专家角色”等）。道具栏有上限。

#### 4. 评分系统
-   调用AI裁判模型，根据预设的五个维度评分（每个维度1-10分）：
    1.  角色设定精准度
    2.  约束条件清晰度
    3.  信息完整度
    4.  迭代深度
    5.  逻辑严谨性
-   返回各维度分数、总分、一段100字内的教练评语（语气平和、理性）。
-   裁判提示词由我们提供，开发者只需传入对话记录和任务信息。

#### 5. 结局系统
-   根据总分匹配结局称号（如35+分 = “未来社区企业家”，25-34 = “数字时代谋士”等）。
-   结局页展示：称号、总分、各关得分、决策风格简述。

### 四、技术需求

#### 1. 技术栈要求
-   **前端**：Next.js (React) + Tailwind CSS
-   **部署**：Vercel（必须支持一键部署）
-   **AI接口**：DeepSeek API（对话模型：deepseek-chat）
-   **后端逻辑**：全部放在 Next.js API Routes 中（不单独搭建后端服务器）
-   **数据存储**：MVP阶段不使用数据库，所有游戏状态存在前端内存中

#### 2. API端点（需开发者实现）

**`POST /api/chat`** - AI对话接口
-   输入：`{ messages: [...], cardContext: { title, task } }`
-   输出：`{ reply: "AI回复文本" }`
-   逻辑：将cardContext注入System Prompt，携带完整对话历史，调用DeepSeek API

**`POST /api/judge`** - AI裁判评分接口
-   输入：`{ conversation: [...], finalAnswer: "string", card: {...}, scoringDimensions: [...] }`
-   输出：`{ scores: { "角色设定": 8, ... }, total: 35, comment: "评语" }`
-   逻辑：使用我们提供的裁判提示词，调用DeepSeek API，要求返回JSON格式

#### 3. 前端页面（需开发者实现）

-   **欢迎页**：标题、副标题、开始按钮、规则简介（折叠面板）
-   **角色选择页**：卡片形式展示可选角色，点击后进入游戏
-   **游戏主界面**（一屏式，响应式）：
    -   **顶部状态栏**：当前关卡、总分、决策币数、道具图标
    -   **左侧面板**：当前任务/事件卡片（标题、描述、任务要求）、骰子区域（危机时显示）、“最终决策结论”输入框
    -   **右侧面板**：AI对话窗口（聊天气泡形式）、消息输入框+发送按钮、提交/重做按钮
-   **评分结果弹窗/页面**：雷达图（五个维度）+ 总分 + 教练评语 + 下一关按钮
-   **商店弹窗**：道具列表，显示价格和购买按钮
-   **结局页**：称号、总分、各关得分列表、总评、再玩一次/返回首页按钮

#### 4. UI/UX要求
-   **配色**：深蓝（#0f172a）为主背景，石板灰（#1e293b）为卡片，天际蓝（#38bdf8）为强调色
-   **风格**：毛玻璃效果、大圆角、细边框、无衬线字体
-   **氛围**：冷静、专注、不浮躁。无弹窗轰炸、无闪烁特效、无搞笑音效
-   **响应式**：桌面端左右两栏布局，移动端自动上下堆叠
-   **移动端优先**：确保在320px宽度的屏幕上也能正常使用
